# Создай полноценный адаптивный лендинг с backend

Создай полностью рабочий проект лендинга для мерча выпускников переподготовки Томского государственного университета (ТГУ) по специальности «Системный аналитик».

Название проекта:

**Мерч ТГУ "САС 101/102"**

Подзаголовок:

**Когда мы стали системными аналитиками.**

Целевая аудитория — преимущественно люди 35+. Дизайн должен быть современным и минималистичным, но не молодежным и не детским.

Это НЕ полноценный интернет-магазин. Сайт предназначен для выбора товаров и отправки предварительной заявки. После заявки менеджер связывается с покупателем по email и уточняет детали.

Используй:

- современный минимализм;
- светлый фон;
- мягкую современную типографику;
- аккуратные скругления;
- умеренное количество декоративных элементов;

- аккуратные hover-эффекты;
- плавное появление элементов;
- плавное открытие модальных окон и FAQ.

- чрезмерно молодежный дизайн;

Упоминание ТГУ допустимо только в текстах.

Сайт должен одинаково хорошо выглядеть на:

- desktop;
- tablet;

# 7. Выбор товаров

Кнопка **"Выбрать"** не отправляет заказ.

Она добавляет товар в текущую заявку.

После выбора:

- карточка визуально показывает состояние "Выбрано";
- увеличивается счетчик выбранных товаров;
- товар появляется в списке заказа.

Пользователь может выбрать несколько разных товаров.

Например:

```text
Футболка
Ежедневник
Ручка
```

Один и тот же товар также можно добавить несколько раз с разными параметрами.

Например:

```text
Футболка — синяя, мужская
Футболка — чёрная, женская
```

Каждая такая позиция должна быть отдельной строкой заявки.

# 8. Оформление заказа

Кнопка:

**Оформление заказа**

открывает отдельное модальное окно.

В модальном окне отображается список выбранных товаров.

Пример:

```text
Футболка — синяя, мужская
Ежедневник — чёрный
Ручка — золотисто-бежевого цвета
```

Для каждой позиции предусмотрена кнопка удаления.

Название товара в списке является ссылкой/кнопкой возврата к карточке товара.

Изменение цвета и других параметров выполняется только в карточке товара.

Не нужно создавать полноценный редактор параметров внутри модального окна.

# 11. Отправка заказа

Это должна быть реальная рабочая отправка, а не демонстрация.

Frontend отправляет данные на FastAPI backend.

Backend:

1. проверяет данные;
2. проверяет защиту от спама;
3. формирует номер заказа;
4. сохраняет заказ в файл;
5. отправляет письмо владельцу сайта.

Формат номера:

```text
YYYYMMDD-HHMMSS-XXX
```

Например:

```text
20260915-134527-381
```

После успешной отправки показать:

**«Заявка №20260915-134527-381 принята. Мы свяжемся с вами по email для уточнения деталей заказа.»**

После успешной отправки:

- очистить выбранные товары;
- очистить форму;
- закрыть модальное окно или показать успешное состояние.

# 12. Сохранение заказов

Каждый заказ обязательно сохранять на сервере как отдельный UTF-8 текстовый файл:

```text
orders/order_YYYY-MM-DD_HH-MM-SS.txt
```

В файле хранить:

- номер заказа;
- дату и время;
- имя;
- email;
- список товаров;
- параметры;
- цвета;
- количество позиций;
- цены.

Например:

```text
Order: 20260915-134527-381
Date: 2026-09-15 13:45:27

Customer:
Name: Иван Иванов
Email: example@example.com

Products:

1. Футболка
   Color: #29488B
   Gender: Мужская
   Price: [PRICE]

2. Ручка
   Color: #B5975D
   Price: [PRICE]
```

# 13. Email

Использовать Yandex Mail SMTP.

Настройки должны находиться в `.env`.

Не хранить SMTP credentials в коде.

Использовать:

```text
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
```

Использовать app password, а не основной пароль аккаунта.

Email получателя заявки должен находиться только на сервере.

Он НЕ должен попадать в frontend JavaScript, HTML или другие клиентские файлы.

Использовать placeholder:

```text
ORDER_EMAIL_TO=...
```

Также предусмотреть:

```text
SMTP_USER=...
SMTP_PASSWORD=...
```

# 26. Deployment

Production-схема:

```text
Internet
   |
   v
 Nginx
   |
   | HTTPS
   v
FastAPI / Uvicorn
   |
   +---- orders/
   |
   +---- logs/
   |
   +---- Yandex SMTP
```

FastAPI запускается через Systemd.

Nginx запускается автоматически.

После перезагрузки сервера оба сервиса должны автоматически запускаться.

Docker НЕ использовать.

FastAPI должен работать непосредственно на Ubuntu 22.04.
