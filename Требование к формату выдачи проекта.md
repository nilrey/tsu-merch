# 29. Формат выдачи полного проекта

Выдай проект **полностью, пофайлово**, а не одним объединённым кодовым блоком.

Сначала покажи итоговую структуру каталогов:

```text
project/
├── frontend/
│   ├── index.html
│   ├── css/
│   │   └── styles.css
│   ├── js/
│   │   ├── app.js
│   │   ├── products.js
│   │   ├── gallery.js
│   │   ├── order.js
│   │   └── feedback.js
│   └── images/
│       └── products/
├── backend/
│   ├── main.py
│   ├── config.py
│   ├── routers/
│   ├── services/
│   └── models/
├── orders/
├── logs/
├── .env.example
├── .gitignore
├── requirements.txt
└── README.md
```

Затем для каждого файла выводи его содержимое отдельно в формате:

```text
FILE: frontend/index.html
```

```html
полное содержимое файла
```

Затем:

```text
FILE: frontend/css/styles.css
```

```css
полное содержимое файла
```

И так далее для **каждого необходимого файла проекта**.

Не сокращай код словами:

- `...`
- `остальной код`
- `аналогично`
- `и т.д.`
- `TODO`
- `здесь добавить код`

Все файлы должны быть выданы полностью.

## Изображения

Поскольку реальные изображения товаров пока отсутствуют, не пытайся вставлять бинарные изображения в ответ.

Создай:

- правильную структуру каталогов;
- конфигурацию путей к изображениям;
- временные placeholder-изображения или ссылки на локальные placeholder-файлы;
- инструкцию в README по их замене.

При этом приложение должно корректно работать даже если реальные фотографии еще не добавлены.

## Конфигурация

Не выдавай реальные секреты.

Создай `.env.example` с понятными placeholder-значениями:

```env
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=your_yandex_email
SMTP_PASSWORD=your_app_password

ORDER_EMAIL_TO=your_order_email
FEEDBACK_EMAIL_TO=your_feedback_email

APP_HOST=127.0.0.1
APP_PORT=8000
APP_DOMAIN=your-domain-or-ip
```

Реальный `.env` не создавать с настоящими credentials.

## Системные файлы

Если для production необходимы конфигурационные файлы Nginx и Systemd, также выдай их полностью отдельными файлами, например:

```text
FILE: deployment/nginx/site.conf
```

и

```text
FILE: deployment/systemd/merch.service
```

Если для них нужен отдельный каталог, добавь его в структуру проекта.

## Инструкция запуска

После всех файлов дай краткую последовательность:

1. создать проект;
2. создать virtual environment;
3. установить зависимости;
4. создать `.env`;
5. запустить локально;
6. проверить frontend;
7. проверить API;
8. настроить Systemd;
9. настроить Nginx;
10. настроить HTTPS;
11. проверить отправку заказа;
12. проверить форму обратной связи.

## Проверка проекта

Перед выдачей результата проверь согласованность файлов между собой:

- все импортируемые Python-модули существуют;
- все frontend-файлы подключены корректно;
- API endpoints совпадают с frontend-запросами;
- названия переменных `.env` совпадают с кодом;
- пути к изображениям совпадают;
- Systemd указывает на правильный FastAPI entrypoint;
- Nginx указывает на правильный порт Uvicorn;
- проект можно запустить без ручного исправления кода.

Главное требование: **результат должен представлять собой полный проект, который можно собрать из выданных файлов и запустить.**
