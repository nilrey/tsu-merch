# Telegram-бот @tgu_sas_bot

## 1. Назначение

Бот используется для проверки интереса к товарам через Telegram-канал `@tgu_sas`.

Для каждого товара:

* отдельная публикация в канале;
* 2–3 фотографии;
* описание товара;
* счетчик заинтересованных;
* индивидуальная кнопка интереса;
* пользователь может отменить заявку;
* один пользователь учитывается один раз для конкретного товара;
* интерес к разным товарам считается независимо;
* порог интереса задается отдельно для каждого товара;
* для кружки порог — 10 человек;
* список заинтересованных хранится в базе;
* публично отображается только количество.

На этапе проверки спроса оформление заказа не реализуется.

# 4. Почему используется venv

Бот запускается не системным Python, а Python из виртуального окружения:

```text
/home/fastapi_user/tgu_sas_bot/venv/bin/python
```

Поэтому установленные для проекта библиотеки не зависят от системных пакетов Ubuntu.

При ручном запуске:

```bash
source venv/bin/activate
python3 bot.py
```

При запуске через systemd активация `venv` не требуется. systemd напрямую использует:

```text
/home/fastapi_user/tgu_sas_bot/venv/bin/python
```

---

# 7. Почему не используется стандартный Telegram Poll

Изначально рассматривалось обычное голосование Telegram.

От него отказались, потому что требуется:

* видеть количество заинтересованных всем подписчикам;
* видеть конкретных заинтересованных администратору;
* не раскрывать список заинтересованных другим подписчикам;
* разрешать пользователю отменить интерес;
* считать интерес отдельно по каждому товару.

Поэтому используется собственная кнопка бота:

```text
[ Выбрать - кружка ]
```

После нажатия:

```text
[ Отменить заявку ]
```

---

# 8. Логика товара

Для кружки:

```text
Порог = 10
```

Счетчик является динамическим.

Например:

```text
0 / 10
1 / 10
...
10 / 10
9 / 10
10 / 10
```

`10` не является постоянным статусом товара.

Это просто условие:

```text
количество заинтересованных >= порог
```

Если после достижения 10 человек кто-то отменил заявку и стало 9, условие снова считается невыполненным.

Дополнительная отметка товара в канале не требуется.

---

# 9. Независимость товаров

Каждый товар имеет собственный счетчик.

Например:

```text
Кружка       7 / 10
Футболка     12 / 15
Блокнот      4 / 10
```

Один пользователь может одновременно проявить интерес к нескольким товарам.

При этом он учитывается только один раз для каждого конкретного товара.

---

# 10. База данных

Используется SQLite:

```text
/home/fastapi_user/tgu_sas_bot/bot.db
```

В ней хранится информация об интересе пользователей.

Для каждого интереса сохраняются:

* ID товара;
* Telegram user ID;
* username;
* имя пользователя.

Для одного пользователя и одного товара действует уникальность:

```text
product_id + user_id
```

Поэтому повторное нажатие не создает дубликат.

Отмена удаляет интерес.

Повторное нажатие снова добавляет его.

---

# 11. Фотографии товара

Фотографии хранятся:

```text
/home/fastapi_user/tgu_sas_bot/images/
```

Например:


Планируется публикация альбома из 2–3 фотографий.

Важно: для надежности лучше использовать `jpg` или `png`. Если исходная фотография находится в BMP, ее рекомендуется предварительно преобразовать в JPG/PNG.

Фотографии публикуются альбомом.

Кнопка и счетчик находятся в отдельном сообщении сразу после альбома.

# 14. Почему обычный запуск недостаточен

Если запустить:

```bash
python3 bot.py
```

через SSH-сессию, процесс может зависеть от этой сессии.

Также после перезагрузки сервера бот сам не запустится.

Поэтому для постоянной работы используется `systemd`.

---

# 15. systemd

Создается:

```text
/etc/systemd/system/tgu_sas_bot.service
```

Содержимое:

```ini
[Unit]
Description=Telegram bot tgu_sas_bot
After=network.target

[Service]
Type=simple
User=fastapi_user
WorkingDirectory=/home/fastapi_user/tgu_sas_bot
ExecStart=/home/fastapi_user/tgu_sas_bot/venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Здесь особенно важна строка:

```ini
ExecStart=/home/fastapi_user/tgu_sas_bot/venv/bin/python bot.py
```

Она гарантирует использование Python из виртуального окружения.

---

# 16. Установка systemd-сервиса

После создания файла:

```bash
sudo systemctl daemon-reload
```

Включить автоматический запуск:

```bash
sudo systemctl enable tgu_sas_bot
```

Запустить:

```bash
sudo systemctl start tgu_sas_bot
```

Проверить:

```bash
sudo systemctl status tgu_sas_bot
```

Нормальный результат:

```text
Active: active (running)
```

---

# 17. Что дает systemd

После настройки:

* бот продолжает работать после закрытия SSH;
* рабочий компьютер можно выключить;
* бот продолжает работать на сервере;
* после перезагрузки сервера бот запускается автоматически;
* при аварийном завершении systemd перезапускает его.

Перезапуск:

```bash
sudo systemctl restart tgu_sas_bot
```

Остановка:

```bash
sudo systemctl stop tgu_sas_bot
```

Запуск:

```bash
sudo systemctl start tgu_sas_bot
```

Просмотр статуса:

```bash
sudo systemctl status tgu_sas_bot
```

Просмотр журнала:

```bash
sudo journalctl -u tgu_sas_bot
```

Последние сообщения:

```bash
sudo journalctl -u tgu_sas_bot -n 50
```

Просмотр журнала в реальном времени:

```bash
sudo journalctl -u tgu_sas_bot -f
```

---

# 18. Важный момент при изменении bot.py

Если бот запущен через systemd, недостаточно изменить `bot.py`.

После изменения нужно:

```bash
sudo systemctl restart tgu_sas_bot
```

Иначе работающий процесс продолжит использовать старую версию Python-кода.

Это также объясняет ситуацию, когда изменение текста кнопки в `bot.py` не сразу появлялось в Telegram.

# 19. Добавление новой картинки

После запуска проекта фотографии находятся здесь:

```text
/home/fastapi_user/tgu_sas_bot/images/
```

Например, нужно добавить:

```text
mug2.jpg
```

Кладем файл:

```text
/home/fastapi_user/tgu_sas_bot/images/mug2.jpg
```

Затем в `bot.py` добавляем его в список:

```python
IMAGES = [
    f"{IMAGE_DIR}/mug.jpg",
    f"{IMAGE_DIR}/mug2.jpg",
]
```

Для трех фотографий:

```python
IMAGES = [
    f"{IMAGE_DIR}/mug.jpg",
    f"{IMAGE_DIR}/mug2.jpg",
    f"{IMAGE_DIR}/label.jpg",
]
```

После изменения:

```bash
sudo systemctl restart tgu_sas_bot
```

# 20. Изменение описания товара

Текст находится в функции формирования сообщения, например:

```python
return (
    f"<b>{PRODUCT_NAME}</b>\n\n"
    f"Проверяем интерес к выпуску кружки с логотипом.\n\n"
    f"<b>Заинтересованы: {count} / {THRESHOLD}</b>"
)
```

Нужно изменить только текст описания:

```python
f"Кружка с логотипом ТГУ.\n\n"
```

После изменения:

```bash
sudo systemctl restart tgu_sas_bot
```

---

# 21. Изменение порога

Для кружки сейчас:

```python
THRESHOLD = 10
```

Если потребуется, например, 15:

```python
THRESHOLD = 15
```

После изменения:

```bash
sudo systemctl restart tgu_sas_bot
```

При дальнейшем развитии порог лучше вынести в таблицу товаров SQLite, чтобы не менять Python-код для каждого нового товара.
